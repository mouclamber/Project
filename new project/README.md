# Anatomy Route — поиск пути лекарства по кровеносной системе

Консольное приложение на C#, которое моделирует кровеносную систему как
взвешенный граф и находит кратчайший (по времени) путь препарата от места
инъекции до целевого органа с помощью **алгоритма Дейкстры**.

## О задаче

**Дано:** кровеносная система, представленная как граф:
- **Вершина** — орган или отдел системы (вена руки, правое предсердие, аорта, мозг…).
- **Ребро** — сосуд между двумя узлами.
- **Вес ребра** — время, за которое препарат проходит по сосуду (в секундах).

**Требуется:** найти путь от места инъекции (точка А) до целевого органа
(точка Б), при котором суммарное время минимально.

Это классическая задача о кратчайшем пути во взвешенном ориентированном
графе с неотрицательными весами. Решается **алгоритмом Дейкстры** за
`O((V + E) · log V)`, где `V` — число вершин, `E` — число рёбер.

### Медицинский контекст

Такая модель используется в:
- **фармакокинетике** — оценка времени достижения препаратом целевого органа;
- **хирургическом планировании** — выбор оптимального доступа;
- **моделировании метастазирования** — путь опухолевых клеток по лимфотоку;
- **нейронавигации** — трактография проводящих путей мозга.

## Как это работает

1. Граф загружается из JSON-файла (или строится в коде).
2. Запускается алгоритм Дейкстры из стартовой вершины.
3. Восстанавливается маршрут по словарю предков `previous`.
4. Результат выводится в консоль: время и последовательность органов.

### Алгоритм Дейкстры (кратко)

- Все расстояния инициализируются «бесконечностью», старт — нулём.
- В очередь с приоритетом кладётся стартовая вершина.
- Пока очередь не пуста:
  - извлекаем вершину с минимальным расстоянием;
  - для каждого соседа считаем новое расстояние;
  - если оно меньше известного — обновляем и кладём в очередь.
- По завершении `distances[v]` — минимальное время до каждой вершины.

## Установка и запуск

### Клонирование

```bash
git clone https://github.com/username/anatomy-route.git
cd anatomy-route
```

### Сборка

```bash
dotnet build
```

### Запуск

```bash
dotnet run --project src/AnatomyRoute.Console
```

Или с указанием файла данных:

```bash
dotnet run --project src/AnatomyRoute.Console -- --data data/circulation.json --start 0 --target 11
```

### Параметры командной строки

| Параметр | Описание | По умолчанию |
|---|---|---|
| `--data` | Путь к JSON-файлу с графом | `data/circulation.json` |
| `--start` | Номер начальной вершины (место инъекции) | `0` |
| `--target` | Номер целевой вершины | `11` |

## Формат данных

Граф хранится в JSON в виде списка смежности:

```json
{
  "graph": {
    "0": [
      { "to": 1, "weight": 2, "name": "Плечевая вена → верхняя полая вена" }
    ],
    "1": [
      { "to": 2, "weight": 1, "name": "Правое предсердие → правый желудочек" }
    ],
    "2": [
      { "to": 3, "weight": 2, "name": "Лёгочная артерия" }
    ]
  }
}
```

### Описание полей

| Поле | Тип | Описание |
|---|---|---|
| `graph` | объект | Список смежности. Ключ — номер вершины (строка из-за особенностей JSON) |
| `to` | int | Номер вершины, куда ведёт ребро |
| `weight` | int | Время прохождения в секундах |
| `name` | string | Название сосуда (для вывода) |

### Принципы

| Принцип | Реализация |
|---|---|
| SRP | Каждый класс делает одно: `Edge` — данные, `DijkstraFinder` — алгоритм, `PathPresenter` — вывод |
| DIP | `DijkstraFinder` зависит от `IGraph`, а не от конкретной реализации |
| OCP | Новый алгоритм (`AStarFinder`) добавляется без правок существующих классов |
| Изоляция слоёв | Domain не ссылается на Infrastructure |

### Покрытые сценарии

**Алгоритм Дейкстры:**
- минимальное время до цели;
- восстановление маршрута;
- недостижимые вершины (расстояние = `int.MaxValue`);
- `start == end`;
- выбор обхода вместо прямого, но длинного пути;
- ветвление (аорта → печень / почки);
- изолированные компоненты графа.
